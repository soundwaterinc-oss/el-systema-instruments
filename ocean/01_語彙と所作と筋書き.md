# 01 語彙と所作と筋書き

ここは語の覚え書き。仕様書（`02_仕様書.md`）はこの語に従う。語が動けば仕様も動く。実装は語に従う ─ ただし**語より先に音を聞く**。

## 一・語

| 語 | あて字 | 役 |
|---|---|---|
| 場 | el-systema-field | ひとつの空間。器が立ち、巫が立ち、響きが行き交う |
| 器 | instrument | 音源を持つ Web Audio 楽器。場へ参じる |
| 巫（ヲサ） | field, おさ | 場を取り仕切る人ならぬ装置。読み、撒き、聞く |
| 葉 | leaf / control | 器の側に置かれる、巫との取次。`registerElSystemaInstrument` |
| 通り道 | transport | 場の言葉が走る道。第二段は ws://localhost：8787 |
| 中継 | hub | 道の真ん中。聞いて放るだけ |
| 気配（ケハイ） | kehai | 器が常に返す、生音から読まれた印（presence / low / high / everSpoke） |
| 御題 | お題 | 巫が器に渡す指示（play / stop / setParam / ramp / loadPreset / snapshot） |
| 祭文（ガイス） | guise / 経 | 一場の楽譜。祭次・応答・楽器・綴び |
| 祭次 | sequence | 時刻で並んだ御題の列。揺らぎは招の時に焼く |

## 二・所作

巫の所作は四つ:

1. **読む** ─ 祭文を頂く。静的検査をする。読めなければ「祭が読めません」と言う。
2. **招く** ─ 招を撒く。実刻が確定する。祭次が走り始める。
3. **聴く** ─ 器の気配を 6Hz で受け、応答の条件を 6Hz で評価する。
4. **撃つ** ─ 応答が満ちれば為（行為）を撃つ。一度／冷却に従う。

器の所作は三つ:

1. **鳴る／止む** ─ 御題に従って音を出し、止める。
2. **気配を返す** ─ 生音から presence/low/high/everSpoke を読み、6Hz で送る。
3. **沈黙を宣る** ─ 一度でも鳴った（everSpoke）後、長く静かなら silence を宣る。

## 三・筋書き

ひとつの祭がどう進むか:

```
1. 場が立つ。中継が ws://localhost:8787 で待つ。
2. 器が参じる。巫が参じる。互いに気配を交わし始める。
3. 巫が祭文を読む。検査が通れば「祭を始める」が押せる。
4. 「祭を始める」── 招が撒かれ、実刻が焼かれる。祭次が走り出す。
5. 器が鳴る。気配が流れる。
6. 巫の神籠りが応答の条件を聞く。満ちれば為が撃たれる。波紋が広がる。
7. 鳴りが収まる。器が静かになる。silence が宣られる。
8. 「ハツイガコ」が応えるなら、戻し相が走る。応えなければ祭は静まる。
9. 「鎮める」── 全器が止む。言上は残る。
10. 「空に戻る」── 場が空く。言上は残る。
```

album（一巻）は子相が複数集まる構造で、manifest が相違の渡りを定義する。それは第三段。

## 四・一不変条件

語は変えてよい。所作の順は変えない。

1. 観測は受動。葉が信号経路を変えない。
2. 既存 UI 操作と御題操作は同次・同結果。
3. 応答規則は人が一行で読める。AI は条件に入らない。
4. 揺らぎは招の時に焼く。実刻は言上に残す。
5. 場のチャンネル名・巫の役の名・祭次/招/応答/言上の表示語は `field/names.js` 一所に閉じ込め、コード本体は無垢のまま。

## 五・差し替えの作法

語を差し替えたいときは `field/names.js` の一所だけを書き換える。所作・信号・命令の形は触らない。`shared/` 直下の三つ（shapes / transport / control）も語に依らない。`hub/server.js` も語に依らない。

そういう作りにしてある。
