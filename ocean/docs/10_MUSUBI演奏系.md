# 10 MUSUBI 演奏系 ─ 流れ（NAGARE）

## 一・問題

静的な御願詞（祭文）と応答だけでは、依代群は**アンビエントに沈む**。
楽器が「記譜できない」性質（パラメータ駆動）なので、人が一音一音を書くことはできず、何もしないと時間方向の構造が失われる。

しかし MUSUBI が DJ 的に**抜き差し・律動の展開・転調**を引けば、ambient を超えた**構築された演奏**になる。

## 二・解 ─ NAGARE（流れ）

MUSUBI の中に**演奏系（NAGARE）**を加える。

```
MUSUBI
├ 結び（bind）         ─ register・通り道（既存）
├ 御願詞（liturgy）    ─ 静的祭次（既存）
├ 神籠り（loop）       ─ 判示評価（既存）
└ 流れ（NAGARE）       ─ 生成的演奏（NEW）
```

NAGARE は**自然関数を作曲源**として、依代のパラメータを時間方向に展開する。

## 三・哲学

- ユタは**自然信仰**：神は自然の中に在る。風・潮・石・木・声、すべてに神が宿る
- 自然関数（1/f、Lorenz、ロジスティック、黄金角、フィボナッチ、ブラウン運動、正弦合成、セルラーオートマトン）は**自然の形を符号化した式**
- これらの式が演奏を駆動する時、演奏は**自然の写し**となる
- **AI は新たな自然**：装置と算式も人の手を離れれば自然の一部。MUSUBI はその一部として演奏を媒介する
- 参照：Ryoji Ikeda の数学的厳密さ・二値（binary）・純度（pure sine）・データ由来の構築。EL-SYSTEMA は柔らかい版を目指す ─ 自然の不規則を含む

## 四・構造

### 4.1 自然関数辞典（[docs/11_自然関数辞典.md](11_自然関数辞典.md) で詳述）

| 関数 | 性格 | 適合 |
|---|---|---|
| **1/f 揺らぎ** | 自然な不規則。中央寄り、稀に極端 | 抜き差し・密度の全般 |
| **ロジスティック写像** | r=3.95 完全カオス。急な遷移 | 突発的な切替・破調 |
| **Lorenz 引力子** | 二葉間を往来する蝶 | 二極の周期的訪問 |
| **黄金角ステップ** | n·φ mod 1、準周期 | 反復せず均等に巡る転調 |
| **フィボナッチ間隔** | 1, 1, 2, 3, 5, 8... 指数的疎密 | 加速する展開 |
| **ブラウン運動** | 連続乱歩 | なめらかな漂い |
| **正弦合成** | 非通約周期の和 | うねりの重なり |
| **セルラーオートマトン** | Rule 30 / 110、二値 | Ikeda 的グリッチ |

各関数は `nextValue(state) -> [0,1]` の共通 API で呼べる。state は持ち越し。

### 4.2 時間スケール

NAGARE は四つの時間スケールで同時に動く：

| 階 | 持続 | 何を駆動 |
|---|---|---|
| **拍（beat）** | 数 100ms | 律動の密度・粒の確率 |
| **節（phrase）** | 8〜32 秒 | 依代の抜き差し（fade in/out） |
| **章（section）** | 1〜3 分 | 転調（scale/root の変更） |
| **巻（movement）** | 5〜15 分 | 境地（mode）の遷移 |

各階で**違う自然関数を割り当てる**ことで、層的な展開ができる。
例：拍=1/f、節=黄金角、章=フィボナッチ、巻=Lorenz。

### 4.3 抜き差し（DJ orchestration）

各依代に**活動包絡（activity envelope）**を持たせる：

- `0` = 沈黙、`1` = 全力で鳴る
- 自然関数の出力を smoothing して使う
- Mode によって smoothing 強度を変える（Ikeda 系は smoothing なし＝二値）

活動包絡は `setParam` 経由で：
- stone-beats: `voice.<石>.on` または `voice.<石>.volume`
- ocean: `ds.level` / `oki.level` / `kg.level`
- 他依代も同様の「強度パラメータ」を持つ

### 4.4 律動展開

打物（stone-beats、mycorrhiza-beat 等）について：
- **密度（density）**を関数で駆動
- **律動（rhythm）**を関数で切替（4/4 → 7/8 → アフリカ → ロジスティック）
- **声単位**で別関数を当てれば polymeter

時間スケール：拍・節。

### 4.5 転調

音階を持つ依代（ocean、planarian-drone、kagome-sound 等）について：
- **基音（root）**を関数で動かす（黄金角 や フィボナッチ間隔が美しい）
- **音階**を章単位で切替
- 急な転調を避けたければ ramp 経由で連続的に

時間スケール：章・節。

### 4.6 境地（Mode） ─ DJ 的キャラクター

MUSUBI に**境地**を選ばせる。各境地は「どの関数をどの階で使うか」「smoothing をどう掛けるか」の組合せ。

| 境地 | 性格 | 主たる関数 | smoothing |
|---|---|---|---|
| **凪（calm）** | 最小限の変化、静かなアンビエント | 1/f + ブラウン | 強い |
| **流（flow）** | 緩やかな成長・退き | 1/f + 黄金角 | 中 |
| **動（motion）** | 律動の活発な切替 | ロジスティック + 1/f | 弱い |
| **嵐（storm）** | カオスで激しい | Lorenz + Lévy | 無し |
| **整（order）** | Ikeda 様、二値、精密 | セルラーオートマトン + フィボナッチ | 二値 |
| **無（void）** | 極小・長い沈黙とバースト | Lévy 飛翔 | スパース |

ユーザが境地を選ぶと、NAGARE が四つの時間スケール全部に対応する関数を組む。

### 4.7 判示との関係

既存の **応答（判示）** は条件発火型。NAGARE は**生成型**。両方が同時に動いてよい：
- 御願詞が骨格（時刻指定の大枠）
- NAGARE がその間を埋める（生成的展開）
- 判示が偶発に応える

つまり MUSUBI 全体は **三層演奏**：固定（祭次）+ 反応（判示）+ 生成（流れ）。

## 六・MUSUBI の動詞化

語が動くと所作が自然になる：

| 動詞 | 意 |
|---|---|
| **結ぶ（musubu）** | 依代を場に登録する |
| **結びを解く（musubi wo toku）** | 接続を切る |
| **結びを通る（musubi wo tooru）** | relay / kehai が往来する |
| **流れを起こす（nagare wo okosu）** | NAGARE を始動する |
| **流れを変える（nagare wo kaeru）** | 境地を切替える |
| **流れを鎮める（nagare wo shizumeru）** | NAGARE のみ止める（祭次は走る） |

## 七・不変条件（NAGARE として）

[02_仕様書要約.md](02_仕様書要約.md) §四の六条を NAGARE にも適用：

1. **観測は受動** ─ NAGARE は relay 経由でだけ作用、信号経路を変えない
2. **判示は一行で読める** ─ NAGARE の各関数も一行 spec で書く
3. **揺らぎは招の時に焼く** ─ 関数の seed は招の時に確定、それ以降は決定論
4. **言上は不滅** ─ NAGARE が打った relay も全て言上に残る
5. **依代は独立** ─ NAGARE が無くても依代は単体で動く
6. **AI は神籠りに入らない** ─ NAGARE の関数は数学的、AI ではない

特に 3 が重要：seed を焼くことで**同じ祭文＋同じ seed なら同じ演奏になる**（再現性）。
違う seed で焼けば違う演奏になる（一期一会）。
