# C6 ─ 祭文スキーマ検証

## 入力
- 検証関数：[shared/el-systema-shapes.js](../../shared/el-systema-shapes.js) ─ メッセージ schema は既にある
- 祭文 schema：**まだ schema 関数が無い** ─ この task で作る
- 既存祭文：[liturgy.example.json](../../liturgy.example.json)、[liturgy.stone-ocean.json](../../liturgy.stone-ocean.json)
- 検証側：[field/field.js](../../field/field.js) の祭文読み込み部

## 出力

### 1. 祭文 schema の検査関数を [shared/el-systema-shapes.js](../../shared/el-systema-shapes.js) に追加

```js
// 祭文の最小 schema
function isLiturgy(o) {
  if (!isObj(o)) return false;
  if (!isString(o.track)) return false;
  if (!isNumber(o.duration) || o.duration <= 0) return false;
  if (!Array.isArray(o.楽器) || o.楽器.length === 0) return false;
  if (!o.楽器.every(isString)) return false;
  if (!Array.isArray(o.祭次)) return false;
  if (!Array.isArray(o.応答)) return false;
  // 各祭次の検査
  for (const seq of o.祭次) {
    if (!isNumber(seq.時) || seq.時 < 0) return false;
    if (!isNumber(seq.揺) || seq.揺 < 0) return false;
    if (!isString(seq.target)) return false;
    if (!o.楽器.includes(seq.target)) return false;     // 未知 target は不許可
    if (!isString(seq.command) || CMDS.indexOf(seq.command) < 0) return false;
    // command ごとの追加検査
    switch (seq.command) {
      case "play": case "stop": case "snapshot": break;
      case "setParam":
        if (!isString(seq.param)) return false;
        if (seq.value === undefined) return false;
        break;
      case "ramp":
        if (!isString(seq.param) || !isNumber(seq.from) || !isNumber(seq.to) || !isNumber(seq.duration)) return false;
        break;
      case "loadPreset":
        if (!isObj(seq.preset)) return false;
        break;
    }
  }
  // 各応答の検査
  for (const r of o.応答) {
    if (!isString(r.名)) return false;
    if (!isObj(r.時)) return false;
    if (!isString(r.時.信号)) return false;
    if (!isString(r.時.演算) || !["<", ">", "<=", ">="].includes(r.時.演算)) return false;
    if (!isNumber(r.時.値)) return false;
    if (r.時.持続 !== undefined && !isNumber(r.時.持続)) return false;
    if (!isObj(r.為)) return false;
    if (!isString(r.為.target)) return false;
    if (!o.楽器.includes(r.為.target)) return false;
    if (!isString(r.為.command)) return false;
    if (r.一度 !== undefined && !isBool(r.一度)) return false;
    if (r.冷却 !== undefined && !isNumber(r.冷却)) return false;
  }
  return true;
}

// 詳しいエラー（どこで何が違ったか）を返すデバッグ版
function explainLiturgy(o) {
  const errs = [];
  if (!isObj(o)) { errs.push("祭文 object ではない"); return errs; }
  if (!isString(o.track)) errs.push("track が無い");
  if (!isNumber(o.duration) || o.duration <= 0) errs.push("duration が正数で無い");
  if (!Array.isArray(o.楽器)) errs.push("楽器 が array で無い");
  if (!Array.isArray(o.祭次)) errs.push("祭次 が array で無い");
  if (!Array.isArray(o.応答)) errs.push("応答 が array で無い");
  // ... 各 entry の詳しい checking
  return errs;
}
```

### 2. field 側で読み込み時に検証

[field/field.js](../../field/field.js) の祭文読み込み箇所：

```js
function loadLiturgy(json) {
  if (!Shapes.isLiturgy(json)) {
    const errs = Shapes.explainLiturgy(json);
    showError("祭が読めません ─\n" + errs.join("\n"));
    state.liturgy = null;
    uiSync();
    return;
  }
  state.liturgy = json;
  state.liturgyName = json.track;
  uiSync();
}
```

### 3. 未知 target の扱い

- 祭文の `楽器` 配列に書かれていない target が祭次／応答に出る → **拒否**
- 場にまだ登録されていない器が `楽器` に出る → 読み込み時は許す（祭文上の宣言）、招の時に未登録ならエラー
- 例：祭文には `geometry-scanner` と書いてあるが、招の時点でその器が場に居ない → ヌジファして「依代が居ません」と言う

### 4. 起動時の検査

招（祭を始める）押下の瞬間に：
1. `Shapes.isLiturgy(state.liturgy)` 再検査
2. `state.liturgy.楽器` の全 id が `state.instruments` に存在するか確認
3. 一つでも無ければ「依代が居ません: X」と表示、招をキャンセル

## 合格条件
1. [liturgy.example.json](../../liturgy.example.json) と [liturgy.stone-ocean.json](../../liturgy.stone-ocean.json) が `isLiturgy` で true
2. 故意に壊した祭文（duration 負数、target を arr に無いものに、応答の演算子を `===` に等）が false で、`explainLiturgy` で具体的にどこが違うか分かる
3. field が壊れた祭文を読んだ時に**祭を始めるボタンが押せない**
4. 招の時に**居ない依代を含む祭文**は招がキャンセルされる
5. field の UI に「祭が読めません」とエラーが具体的に表示される

## 触ってはいけないもの
- 既存 schema（メッセージ schema は触らない、追加するだけ）
- 既存 [liturgy.example.json](../../liturgy.example.json) と [liturgy.stone-ocean.json](../../liturgy.stone-ocean.json) の中身

## 注意
- 演算子は `>`、`<`、`>=`、`<=` の四つを許す。`==`、`!=` は禁ずる（仕様書「人が一行で読める」原則）
- 信号名（`presence:ocean` 等）の形式は `<種>:<id>` ─ `<種>` は `presence/silence/low/high/density` 等の今ある kehai 量
- 知らない信号名は **false 評価**（落とさない）
