# C4 ─ 言上（コトダマ）の不滅

## 入力
- 実装：[hub/server.js](../../hub/server.js) の `appendLog`、[field/field.js](../../field/field.js) の言上表示
- 仕様：[01_語彙と所作と筋書き.md](../../01_語彙と所作と筋書き.md) §一「言上 = 不滅の記録」、[02_仕様書要約.md](../../docs/02_仕様書要約.md) §四・不変条件 4

## 出力
言上が**消えない**ことを保証する三層：

### 層 1：hub の追記ログ（既存 + 強化）

- 既存：[hub/server.js](../../hub/server.js) が `logs/YYYY-MM-DD.jsonl` に追記
- 強化（[C1_hub堅化](C1_hub堅化.md) §2 と整合）：
  - SIGINT/SIGTERM で flush を待つ
  - 書き込み失敗時の **stderr ログ**（既に出ている）
  - ファイル名は **JST**（jst の今日）か **UTC** かを明示（コードコメントに記す ─ 既存は process timezone）

### 層 2：場のリプレイ可能性

JSONL を後から再生できる：

- `node hub/replay.js logs/2026-05-23.jsonl` で当日の言上を hub 経由で再放出（タイムスタンプを保ったまま）
- 用途：祭の事後検証、デバッグ、後で「あの瞬間」を再生

```js
// hub/replay.js（新規）
// 使い方: node hub/replay.js <jsonl-path> [--rate=1.0]
const fs = require("fs");
const path = require("path");
const WebSocket = require("ws");

const jsonlPath = process.argv[2];
const rate = parseFloat((process.argv.find(a => a.startsWith("--rate=")) || "--rate=1.0").split("=")[1]);
const wsUrl = process.env.WS_URL || "ws://localhost:8787";

if (!jsonlPath) { console.error("usage: node replay.js <path> [--rate=N]"); process.exit(2); }

const lines = fs.readFileSync(jsonlPath, "utf8").split(/\r?\n/).filter(Boolean);
const messages = lines.map(JSON.parse);
if (!messages.length) { console.error("empty"); process.exit(2); }

const t0 = messages[0].at;
const realStart = Date.now();
const ws = new WebSocket(wsUrl);
ws.on("open", () => {
  messages.forEach(m => {
    const wait = (m.at - t0) / rate;
    setTimeout(() => { try { ws.send(JSON.stringify(m)); } catch (_) {} }, wait);
  });
  setTimeout(() => ws.close(), ((messages[messages.length-1].at - t0) / rate) + 1000);
});
```

### 層 3：field の言上窓は読み取り専用

- field の「ユンタクの河」は **append のみ**、編集・削除不可
- 言上は `kotodama` 型として hub に流す（既存 schema 通り）
- 人の打鍵は `kotodama {from:"user", text:"..."}` で流す
- 言上窓に出すのは全 `t in {relay, kehai, silence, ack, err, maneki, kotodama}` のうち**人が読む価値があるもの**のみ：
  - relay / maneki / silence / kotodama / err は常に表示
  - kehai は数値線として（マブイ計）、テキスト窓には出さない（流量過多）

### 層 4：session 単位の書き出し

- field の「書き出し」ボタンで、招から鎮め／空に戻るまでの言上を JSONL でダウンロード
- session 開始時刻と終了時刻を含むメタヘッダを先頭に付ける（コメント JSONL の最初の行を `{"t":"meta", "session":"...", "started":..., "ended":...}` にする）

## 合格条件
1. 場が立っている間、`logs/YYYY-MM-DD.jsonl` が秒ごとに増える
2. hub プロセスを SIGINT で止めても直前の言上が完全に書かれている
3. `node hub/replay.js logs/<日付>.jsonl` を流し、field を別端末で立ててリプレイが visualization と一致する
4. field の「書き出し」ボタンで session 単位の jsonl が手元にダウンロードできる
5. 人の `kotodama` 入力が言上に記録される（再起動後も残る）

## 触ってはいけないもの
- メッセージ schema
- 過去ログの追記以外の編集（言上は不滅）

## 注意
- ログのローテーション・圧縮はこの task のスコープ外
- 個人情報を含む可能性のある `kotodama` テキストは**コード上は素通し**。ユーザの管理責任
- hub は単一マシン localhost 想定。リモート同期は別 task
