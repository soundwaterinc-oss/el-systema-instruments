# L8 ─ 依代の演奏面（NAGARE 駆動受け入れの整備）

## 入力
- MUSUBI 演奏系設計：[docs/10_MUSUBI演奏系.md](../../docs/10_MUSUBI演奏系.md)
- 接続契約：[docs/09_接続契約.md](../../docs/09_接続契約.md)
- M2 のマッピング想定：[tasks/codex/M2_抜き差しと展開.md §1](../codex/M2_抜き差しと展開.md)

## 目的

NAGARE が DJ 的に各依代を「抜き差し・律動展開・転調」する時、依代側に最小限の対応 API が無いと弾かれる。
依代別に**3 つの面**が要る：

| 面 | 役 | 必要なパラメータ |
|---|---|---|
| **抜き差し** | NAGARE が voice の活動度を上下させる | voice 別 volume または on/off、ramp 可能 |
| **律動** | 打物の密度・激しさ | density / energy / intensity 系 |
| **転調** | 音階・基音の変更 | root / scale 系 |

stone-beats と ocean は既に三面とも揃っている（[docs/09_接続契約.md §六](../../docs/09_接続契約.md)）。
他依代を順に整備する。

## 出力

各依代リポジトリで、以下を**最小限**に追加：

### 共通：[docs/09_接続契約.md §六](../../docs/09_接続契約.md) への追記

接続済み依代のパラメータ表を [docs/09_接続契約.md §六](../../docs/09_接続契約.md) に**写経**して、NAGARE が読める形にする。

```
### <依代 id>
- 抜き差し：voice 別 → param 名（例: `voice.<voice>.volume`）
- 律動：→ param 名（例: `density`）
- 転調：→ param 名（例: `root`）
- 各 param の値域と既定値
```

### 依代別の補修内訳

#### geometry-scanner
- **抜き差し**：`bassLevel`, `droneLevel`, `percussionLevel` の三声 ─ 既にある、map に追加するだけ
- **律動**：`bpm` を関数で動かす？ あるいは `selectedRhythm` を `["Kecak Cycle", "Polyrhythm", ...]` から選ぶ
- **転調**：`selectedRootNote` を `["C","D","E",...]` から選ぶ、`selectedScale` も
- 不足：おそらく無し ─ 既存 API で全部出来る

#### particle-noise
- **抜き差し**：engine 別 `masterGain`（particle, metallic, physical）─ ドット表記 `particle.masterGain` を使う
- **律動**：engine 別 `density`、`rate`
- **転調**：無い（ノイズ楽器）─ skip
- 不足：おそらく無し

#### kagome-sound
- **抜き差し**：voice / engine の単位を要確認 ─ Poly Engine の構造を読む必要
- **律動**：律動が独立に有るかは要確認
- **転調**：`selectedScale` 等 ─ 要確認
- 不足：**要調査**

#### mycorrhiza-beat
- **抜き差し**：beat / voice 単位 ─ 要確認
- **律動**：bpm / density ─ 要確認
- **転調**：drum 系なので転調は無いかも
- 不足：**要調査**

#### moss-reservoir
- **抜き差し**：drone の各層 ─ 要確認
- **律動**：drone なので無いか緩い
- **転調**：root / scale ─ 要確認
- 不足：**要調査**

#### planarian-drone
- **抜き差し**：drone のレイヤー ─ 要確認
- **律動**：drone なので無い
- **転調**：root / scale ─ 要確認
- 不足：**要調査**

#### CellnoiseGenerator
- ParticleNoise と同様の engine 構造 ─ 要確認
- 不足：**要調査**

### 補修が要る場合

依代側のコードを読んで、不足する**最小の setParam を追加**：

```js
// 例：droneレイヤを on/off できないなら、register の setParam に追加
setParam: (name, value) => {
  // ... 既存処理
  if (name === "layer.<n>.on") {
    layers[parseInt(n)].on = !!value;
    return;
  }
}
```

絶対に**新しい音色を作らない**。既にあるものを「場から触れる窓」にするだけ。

### 報告

各依代について以下を報告：

```
### <依代 id>
- 抜き差しの param：<完了/補修した/不可能>
- 律動の param：<完了/補修した/不可能>
- 転調の param：<完了/補修した/不可能>
- 各 param の値域と既定値（[docs/09_接続契約.md §六](docs/09_接続契約.md) に追記済）
```

## 合格条件

1. すべての接続済み依代について、3 面（抜き差し・律動・転調）の状態が [docs/09_接続契約.md §六](../../docs/09_接続契約.md) に明記されている
2. 「不可能」と判定した面は、その理由が書かれている（例：drone なので律動なし）
3. 補修したコミットがある場合、commit hash が言上に残る
4. **新しい音色は追加しない**（CC が監査）

## 触ってはいけないもの

- 既存の音色（[stone-beats](../../stone-beats.html) / [ocean](../../ocean.html) ですら手を付けない）
- 既存の UI レイアウト
- 音色設計パラメータ（a_mix 等のディテール）

## 注意

- 「不可能」を恐れない ─ 律動が無い drone 依代に律動を強制しない
- マッピングが揃った依代から NAGARE が駆動できる ─ 揃わない依代は静置でも構わない
- このタスクは [M2_抜き差しと展開.md](../codex/M2_抜き差しと展開.md) の `ElSystemaInstrumentMap` を完成させる前提
