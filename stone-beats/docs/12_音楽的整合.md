# 12 音楽的整合 ─ 9 声を一つの和声時空に束ねる

## 一・問題

[10_MUSUBI演奏系.md](10_MUSUBI演奏系.md) の NAGARE は四つの時間スケール（拍・節・章・巻）に自然関数を割り、依代ごとに 抜き差し/律動/転調 を駆動する。
しかし**駆動先は依代ごとに独立**で、ocean の root と planarian-drone の rootNote には関係がない。stone-beats の bpm と mycorrhiza-beat の bpm も無関係に揺れる。

結果：9 依代が**並列に揺らぐアンビエント**にはなるが、和声・律動が**一つの音楽体**として組み上がらない。

## 二・解 ─ MUSUBI 音楽状態（musical state）

MUSUBI に**一つの音楽状態**を持たせる。各依代はそれを native param に翻訳する。

```
MUSUBI
├ 結び（bind）
├ 御願詞（liturgy）
├ 神籠り（loop）
├ 流れ（NAGARE）             ─ 時間方向の生成
└ 音楽状態（music）           ─ 和声・律動の共通時空（NEW）
```

音楽状態は relay 経由（`target: "MUSUBI"`、M4 経路）でも 祭文 でも NAGARE 内部からも書き換えられる。書き換わると**全依代に同時に**翻訳が走る。

### 状態 schema

```js
{
  key:      0..11,           // 半音番号、C=0 D=2 E=4 F=5 G=7 A=9 B=11
  mode:     "凪"|"琉球"|"平調子"|"陰旋"|"アイヌ"|"シベリア"|"モンゴル"|"スレンドロ"|"ペログ"|"マカーム"|"バイラヴィ"|"無",
  bpm:      40..180,         // master tempo
  bar:      derived,         // 招から数えた小節数（4/4 既定、4 拍 = 1 小節）
  beat:     derived,         // 招からの拍数 = (経過秒 × bpm / 60)
  tension:  0..1,            // 派生：依代群の presence 平均
  register: -1..+1           // 全体の octave bias。-1=低、0=中、+1=高
}
```

`setParam` 経路：

| param 名 | 値 | 為 |
|---|---|---|
| `music.key` | `"C"` `"D"` `"F#"` … or 0..11 | 全依代の root 再計算 |
| `music.mode` | 上記 12 種 | 全依代の scale 再計算 |
| `music.bpm` | 数 | 全依代の bpm を `bpm × tempoRatio` で再送 |
| `music.register` | -1..1 | 全依代の octave bias |

### 方言として鳴る ─ 詭弁の不在

完全一致するのは kagome の native 取り揃えと平調子の ocean/planarian など限られた組合せだけ。**残りは皆「方言」として鳴る**。

これは欠陥ではなく**設計の核**：

- 琉球音階を 9 依代で同時に鳴らすとき、kagome は本物の琉球音階を語り、ocean は「ペンタトニックなまり」で応え、planarian は「ミクソリディアンなまり」で唱える
- 同じ祈りが**九つの依代＝九つの口**から、それぞれの母語で出てくる
- 完全に揃わせる必要はない。**揃わなさが多声を成す**

ユタが「いま降りているのは琉球の神」と告げる時、各依代はそれを自分の知る最も近い言葉に翻訳して同時に鳴らす ─ それが**下ろす**の意。

**シャーマニズムに詭弁はない**。マカーム本来の四分音を 12-TET で受けるのも、シベリア倍音歌を pentatonic で代弁するのも、弁解の要らぬ事実 ─ 翻訳でないものは何もなく、すべてが翻訳である。完全な転写を求めることの方が、ここでは異物となる。

打物・粒子・cell 系（stone-beats / mycorrhiza-beat / particle-noise / cell-noise）は scale 概念を持たない（声を持たぬ依代）。これらは `music.mode` を無視するが、`mode === "凪"` の時のみ特別に**極小モード**（pulseRate を遅く、burstDensity を疎に等）に入る。

## 四・root の符号化 ⇄ 変換

依代によって root の表現が異なる：

| 依代 | 符号 | 範囲・典型値 |
|---|---|---|
| ocean | Hz | `OCEAN_ROOTS = [55, 65, 73, 82, 87, 98, 110, 123, 138]` |
| moss-reservoir | Hz | rootHz 24-108 |
| cell-noise | Hz | pitchBase（連続） |
| planarian-drone | 半音 index | `PLANARIAN_ROOTS = [0,2,4,5,7,9,11]` (C D E F G A B) |
| geometry-scanner | 文字 | `GEOMETRY_ROOTS = ["C","D","Eb","F","G","A","Bb"]` |
| kagome-sound | （無） | Hz 配列の最低音が root。customScale を生成して与える |

### 変換式

canonical key（0-11 半音）から各 native への：

```js
// key: 0..11、register: -1..+1、A4 = 440 Hz
function keyToHz(key, octaveBase) {
  // octaveBase: 例 ocean 用は 2（C2=65.41）、moss 用は 1（C1=32.70）
  const midi = key + 12 * (octaveBase + register);
  return 440 * Math.pow(2, (midi - 69) / 12);
}

function keyToLetter(key) {
  return ["C","C#","D","Eb","E","F","F#","G","Ab","A","Bb","B"][key];
}

function clampToNative(key, nativeIndices) {
  // 例: planarian の [0,2,4,5,7,9,11] へ key=1 (C#) を入れたら nativeIndices の最近接
  let best = nativeIndices[0], bestDist = 12;
  for (const n of nativeIndices) {
    const d = Math.min((key - n + 12) % 12, (n - key + 12) % 12);
    if (d < bestDist) { best = n; bestDist = d; }
  }
  return best;
}
```

### Universal key と clamp（ずれを抱く）

planarian の roots `[0,2,4,5,7,9,11]` と geometry の `[0,2,3,5,7,9,10]` の **共通集合は [0,2,5,7,9] = C D F G A**（major pentatonic の音）。

**この 5 つは全依代が同じ root で揃う**。他のキー（C#・E♭・B♭ 等）を選ぶと planarian や geometry が clamp で隣接音にずれる。

**この clamp ずれは方言の一部として推奨する**。シャーマニズムの場では、依代が御神体を「正確に」翻訳することよりも、各自の能う限りで応える**多声**の方が重い。**ずれて鳴る依代こそ、別の口で同じ祈りを唱えている**。

祭文の作法：

- **C / D / F / G / A** ─ 全依代が完全一致する「澄んだ調」。儀礼の主軸に置く
- **他キー** ─ planarian/geometry は方言で応える。ずれごと音楽として鳴る
- **アイヌ・シベリア・モンゴル** ─ kagome に native presets が無いので customScale で度数から立てる。北方の祈りが琉球の場に下ろされる
- **マカーム / バイラヴィ** ─ 四分音は kagome microtonal で正確に、他依代は 12-TET の格子で。同じ祈りを違う口で唱える

### kagome の動的 customScale

kagome は scalePreset を選んでも root は C4=261.63 Hz 固定。master key で転調したい時は：

```js
function makeKagomeCustomScale(key, modeDegrees, baseOct) {
  // modeDegrees: 例 平調子なら [0, 2, 3, 7, 8]
  // baseOct: 4 が中央 (C4=261.63)
  const baseMidi = 12 * baseOct + key;
  return modeDegrees.map(d => 440 * Math.pow(2, (baseMidi + d - 69) / 12));
}
// 結果: customScale パラメータに「,」区切りで送る
// 例: G + 平調子 → "196.00,220.00,233.08,293.66,311.13"
```

NAGARE の kagome アダプタは `music.key` 変化時に上記を計算し、`setParam("scaleCategory", "custom")` + `setParam("customScale", hzStr)` を送る。

## 五・register zone と tempoRatio

### 周波数帯（register zone）

依代を 3 つの zone に振り、master key 共通のまま **音域を分散**する：

| zone | 周波数中心 | 依代 | 役 |
|---|---|---|---|
| **bass** | 24-130 Hz | ocean / moss-reservoir | 持続する低音、和声の基盤 |
| **mid** | 130-520 Hz | planarian-drone / kagome-sound | 旋律・和声、人声に近い帯域 |
| **hi**   | 520 Hz - | mycorrhiza-beat / stone-beats / particle-noise / geometry-scanner / cell-noise | 律動・倍音・グリッチ |

`music.register` で全体に octave bias を掛ける時、zone 内でのみ動かす（bass を mid に押し上げない、相対関係を保つ）。

### tempoRatio（多声リズム）

依代ごとに master BPM への**整数比**を持たせる：

| 依代 | tempoRatio（既定） | 役 | 揺動範囲 |
|---|---|---|---|
| mycorrhiza-beat | **1** | master 拍の基準声 | ─ |
| stone-beats | **1** または **2** | 律動の主、2 倍でトリル | 動・嵐境地で 2 |
| kagome-sound | **1** または **2/3** | 主、または hemiola | 流境地で時々 2/3 |
| moss-reservoir | **1/2** | half-time（ドローン的） | 凪・無境地で 1/4 |
| particle-noise | **1**（rate = bpm/60 × N）| 粒の発生率は master 由来 | 嵐境地で N を上げる |
| geometry-scanner | **1** または **3/2** | 主、または 1.5 倍で hemiola | 動境地で 3/2 |
| ocean | **1/2**（drift = bpm × 0.5）| 流れは half-time | ─ |
| planarian-drone | ─ | 拍を持たない | ─ |
| cell-noise | **1/8** または **1/4** | sub-harmonic pulse | 整境地で 1/8、嵐で 1/4 |

NAGARE が `music.bpm` を読んで各依代に native bpm を送る時、必ず `bpm × ratio` を掛ける。

**整数比のみ**を使う（1, 2, 1/2, 2/3, 3/2, 4/3, 1/4, 1/8）。無理数や複雑な比は使わない ─ 音楽性は単純比に宿る。

## 六・転調策（modulation policy）

`music.key` または `music.mode` 変化時の追従方針：

| 策 | 動 | 使う場面 |
|---|---|---|
| **immediate** | 4 秒 ramp で全依代が同時 | 嵐境地、急な転換 |
| **phrase-aligned** | 次の節境界（既定 8 小節 = 4×8/bpm × 60 秒）まで遅延 | 流・動境地 |
| **section-aligned** | 次の章境界（32 小節）まで遅延 | 整境地 |
| **voice-led** | 共通音を保ったまま段階的に動く（下記） | 凪・無・琉球境地 |

依代ごとに policy 既定を持ち（接続契約 §九）、policy は祭文の `転調策[]` で個別上書きできる。

### voice-led アルゴリズム

C 平調子 → F 平調子 のような転調で、**共通音を保ちつつ気づかせず**移る：

```js
function voiceLed(oldKey, oldMode, newKey, newMode, durationSec) {
  // 1. 共通音セットを計算
  const oldPCS = pitchClassSet(oldKey, oldMode);  // {0,2,3,7,8} for C平調子
  const newPCS = pitchClassSet(newKey, newMode);  // {5,7,8,0,1} for F平調子
  const common = oldPCS.filter(p => newPCS.includes(p));  // {0,7,8}

  // 2. 三段階の relay 列を生成
  // 段階 A (0..durationSec/3): 旧 scale だが、共通音以外の音量を 50% に
  //   各依代の native voice/layer のうち non-common を attenuate
  //   ocean: 例 ds (bass) は root 共通なので維持、oki (mid) は scale 由来で attenuate
  //   planarian: layer.0 keep, layer.1/2 level → 0.5
  //   kagome: customScale を common のみで再構成
  
  // 段階 B (durationSec/3..2/3): scale を newMode に切替（root はまだ old）
  //   ocean.scale, kagome.customScale, planarian.targetScale を送る
  
  // 段階 C (2/3..durationSec): root を ramp で new に
  //   ocean.root を ramp、planarian.rootNote を setParam、
  //   kagome.customScale を newKey に再計算
  
  return relays;
}

function pitchClassSet(key, mode) {
  const degrees = CANONICAL_MODES[mode];  // 例 平調子 → [0,2,3,7,8]
  return degrees.map(d => (key + d) % 12);
}
```

凪境地で `voice-led` 既定にすると、長時間奏のあいだに気づかぬうちに key が動いていく ─ アンビエント転調の効果。

## 七・`harmony:<id>` 信号

依代の今の音色が master 音楽状態とどれだけ親和しているかを 0..1 で出す。判示（応答）の条件で使える。

```js
function harmony(id, music) {
  const inst = state.instruments[id];
  if (!inst.snapshot) return 1.0;  // snapshot 不能なら親和度 max

  // 音階を持たない依代は常に 1.0（拍系は和声衝突しない）
  if (!INSTRUMENT_MUSICAL_CAPS[id].scale) return 1.0;

  // 依代の現 root / scale を native から canonical に逆変換
  const instPCS = inferPitchClassSet(id, inst.snapshot);  // 例 ocean=ヒラジョシ@C → {0,2,3,7,8}
  const masterPCS = pitchClassSet(music.key, music.mode); // 例 琉球@C → {0,4,5,7,11}
  // 共通音は {0,7} ─ 2/5 が overlap、harmony ≈ 0.40 ─ 同じ場の方言として「離れた近所」の関係

  // 共通音の比率
  const overlap = instPCS.filter(p => masterPCS.includes(p)).length;
  return overlap / instPCS.length;
}
```

応答での使用例：

```json
{
  "名": "海と籠目が合わせたら、菌糸が応える",
  "時": { "信号": "harmony:ocean", "演算": ">", "値": 0.8, "持続": 4 },
  "為": { "target": "mycorrhiza-beat", "command": "ramp",
          "param": "fx.resonance", "from": 0.4, "to": 0.7, "duration": 10 }
}
```

逆に `harmony:cell-noise < 0.3` で「響き合わぬ時こそ整境地を強める」みたいな逆転判示も書ける。

## 八・境地と音楽既定

[10_MUSUBI演奏系.md §4.6](10_MUSUBI演奏系.md) の 6 境地に音楽既定を結ぶ：

| 境地 | 推奨 mode | 推奨 key | 推奨 bpm | 転調策既定 | tempoRatio 揺らし |
|---|---|---|---|---|---|
| **凪** | 凪 / 琉球 / アイヌ | C / G | 50-72 | voice-led | 全 1:1 |
| **流** | 琉球 / 平調子 / モンゴル / バイラヴィ | D / G / A | 72-96 | phrase-aligned | kagome 時々 2/3 |
| **動** | スレンドロ / ペログ / マカーム | D / A / F | 96-128 | phrase-aligned | stone 2、geo 3/2 |
| **嵐** | マカーム / 陰旋 / シベリア / 無 | 任意（方言推奨） | 110-140 | immediate | particle N 増、stone 2 |
| **整** | 無 / 凪 | C / G（quantized） | 100-120 | section-aligned | 全 ratio 整数厳密、cell 1/8 |
| **無境地** | 凪 / アイヌ（4 音極小）| C | 40-60 | voice-led | tempoRatio 概念ほぼ無効 |

mode 選択の文化的指針：

- **儀礼の冒頭・終端**は 凪・琉球（ユタの場の本来の調）、または アイヌ（4 音極小・場が静まる）
- **流境地の祈祷**は モンゴル長唄（草原的、装飾豊か）/ バイラヴィ（深い帰依）
- **動境地での律動の盛り上がり**は スレンドロ / ペログ（ガムラン由来、複数声部の絡み）
- **嵐境地での激情**は マカーム（旋舞の加速）/ 陰旋（鬼神を呼ぶ）/ シベリア（喉歌の倍音圧）
- **整境地での Ikeda 様**は 無（chromatic）または 凪（root+5 の極小）

これらは**既定**。境地切替時に NAGARE が音楽状態を上書き、ただし祭文の `音楽` block があれば祭文を優先する。

bpm range は「ここを中心に揺れる」ガイド。NAGARE の 拍 階関数（pink/logistic 等）が `min + value × (max-min)` で実 bpm を生む。

## 九・祭文への `音楽` block 拡張

[shared/el-systema-shapes.js](../shared/el-systema-shapes.js) の祭文 schema に optional な top-level `音楽` を許す：

```json
{
  "album": "EL-SYSTEMA",
  "track": "九の輪",
  "duration": 600,
  "楽器": [ ... ],
  "音楽": {
    "key": "C",
    "mode": "凪",
    "bpm": 60,
    "register": -0.2,
    "転調策": [
      { "時": 60,  "key": "G",  "policy": "voice-led",       "duration": 16 },
      { "時": 150, "mode": "スレンドロ", "policy": "phrase-aligned" },
      { "時": 270, "mode": "マカーム", "key": "F#", "policy": "immediate" },
      { "時": 390, "mode": "凪", "bpm": 110, "policy": "section-aligned" },
      { "時": 480, "key": "C", "mode": "凪", "bpm": 50, "policy": "voice-led", "duration": 30 }
    ]
  },
  "祭次": [ ... ],
  "応答": [ ... ]
}
```

- `音楽` block 不在なら境地既定を使う（後方互換）
- `転調策[i].時` の各エントリは内部で `target: "MUSUBI"` の setParam として展開（M4 経路）
- `duration` は ramp 系策（voice-led/immediate）の総時間、phrase/section-aligned では境界待機時間の最大

## 十・接続契約への追加（09 §六拡張）

各依代の契約に **音楽アダプタ仕様**を追記する。書式：

```
### <依代名>（音楽アダプタ）
- accept: ["music.key", "music.mode", "music.bpm", "music.register"] のうち反応
- canonical → native マッピング:
  - 凪         → <native>
  - 琉球       → <native>
  - 平調子     → <native>
  - 陰旋       → <native>
  - アイヌ     → <native>
  - シベリア   → <native>
  - モンゴル   → <native>

  - ペログ     → <native>
  - マカーム   → <native>
  - バイラヴィ → <native>
  - 無         → <native>
```

依代側コードは `setParam("music.<field>", value)` を受け、内部 `applyMusic(state)` で native に翻訳する。**翻訳テーブルは依代側に持つ**（場が全依代の癖を知らなくて良い）。
